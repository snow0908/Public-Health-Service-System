1 项目背景与问题

公共卫生服务系统以表单数据填报与存储为核心业务形态，覆盖居民健康档案管理、健康教育、预防接种、0-6 岁儿童健康管理、孕产妇健康管理、老年人健康管理、慢性病患者健康管理等 12 类服务项目。国家基本公共卫生服务规范已发布至第三版，各地在此基础上叠加地方性政策要求，导致表单内容频繁调整。

现状痛点：传统硬编码表单开发模式下，每次政策调整都需要研发介入，开发—测试—上线周期长、成本高，且各地表单配置差异大、逻辑校验不清，易产生数据不一致问题，已成为基层公卫工作的突出痛点。

2026 年，四部门联合印发《关于做好 2026 年基本公共卫生服务工作的通知》（国卫基层发〔2026〕19 号），对服务方式、服务范围和质量要求提出新要求，进一步凸显了表单动态配置能力的必要性。

2 建设目标

0 代码业务人员自主创建、修改、发布表单
小时级政策调整后表单变更响应用时
100%历史数据安全保留、新旧版本平滑过渡

四项目标

  • G1 业务人员自主设计：让公卫业务管理人员无需编程即可完成表单的创建、修改与发布，降低对研发的依赖。
  • G2 政策快速响应：国家或地方政策调整时，可在小时级完成表单变更并上线。
  • G3 数据标准对齐：表单字段与卫生信息数据元目录（WS 363）等国家标准对齐，保障数据互操作性。
  • G4 历史数据安全：表单版本变更后，历史数据完整保留，新旧版本平滑过渡。

3 用户与角色

业
公卫业务管理人员（表单设计者）

各县区/机构业务骨干，具备业务与政策知识、无编程能力。主要诉求：拖拽式快速改表、引用已有范式、预览校验。

审
主管部门/审核人

审批待发布表单版本，把关数据标准符合性，决定发布/回退。

录
基层填报人员

在表单设计引擎发布后的业务页面上填报数据，是历史数据的主要生产者。

维
系统管理员

维护 WS 363 数据元目录、权限、操作日志与系统级参数。

研
研发人员

维护表单引擎本身与渲染运行时，原则上不再直接改单一业务表单。

数
数据/上报人员

导出、上报按标准对齐后的结构化数据，校验字段名与码值。

4 术语定义

术语定义
表单（Form）面向某一业务场景的一组字段集合，如「个人基本信息表」，是版本管理的最小单元。
区块（Section/分组）表单内的逻辑分组，对应档案维护中的 fv-group 与完整度统计分区，如「既往史」「个人健康标识」。
字段（Field）表单中的最小数据采集单元，具备类型、是否必填、数据元标识等属性。
数据元（Data Element）卫生信息数据元目录（WS 363）中定义的标准数据项，含标识符、名称、值域、数据类型等。
校验规则（Rule）字段级校验（必填、格式、范围、枚举）与表达式级联动（条件显隐、值联动）的统称。
草稿 / 待审 / 已发布表单版本的生命周期状态：编辑中的草稿、提交审核、审核通过并生效。
版本快照表单某一次发布时保存的完整结构快照，用于回滚与历史数据映射。
值域目录可复用的选项字典（如 ABO 血型、文化程度），供多个字段引用，保证码值一致。

5 范围界定

本引擎负责：表单结构定义、字段可视化编排、校验规则配置、WS363 数据元对齐、版本管理与发布、历史数据映射。
不在本引擎范围：具体业务数据的填报执行（由发布后的业务页面承担）、业务系统底层存储、国标数据元目录维护工具本身（仅提供引用与搜索）。

6 功能需求

FR-01 表单全生命周期管理 核心 · 必做

表单从创建到退役的完整管理，支持新建、复制、归档、删除（逻辑删除）。

功能点说明优先级
新建表单支持从空白开始，或从系统范式模板（个人基本信息表、随访表等）复制创建。高
表单属性表单名称、业务标签（所属 12 类服务项目）、图标、适用机构范围、是否启用。高
复制表单以某一版本为基底克隆出草稿，便于地方性微调，减少重复搭建。中
归档/删除停用并归档历史表单；有历史数据的表单不允许物理删除。中
菜单联动发布后自动注册/更新系统菜单项（参考框架.js 的 form-maintenance 模式）。高

FR-02 可视化设计画布（所见即所得） 核心 · 必做

画布即渲染器：以贴近`档案维护.html`的 fv-card / fv-group / hp-row / hp-cell 范式实时渲染表单结构，业务人员所见即所得。

功能点说明优先级
三栏布局左侧组件/结构面板 + 中间设计画布 + 右侧属性面板（见 §9 界面规范）。高
字段拖拽从字段组件库拖拽字段入画布分区；画布内可拖动排序、跨分区移动。高
区块管理新增/重命名/删除分区；分区可配置是否计入完整度（对应表单维护.html 的完整度分区）。高
排列模式单列整行（hp-row）、双列（hp-row two-col / hp-cell）、多行联动字段（.ig 内联组）、明细表格（mini-tbl）。高
选中与属性点击画布字段高亮并联动右侧属性面板；删除按钮、复制字段。高
实时预览「预览」以只读态打开渲染效果，并模拟基层填报视图。中

FR-03 字段组件库与字段属性 核心 · 必做

提供与档案维护表单一致的控件类型，作为可复用组件。

组件类型渲染控件典型字段
单行文本.ctl input姓名、证件号、联系电话
多行文本textarea地址、备注
数字number/带单位身高、体重、BMI、血糖值
日期 / 时间type="date/time"出生日期、随访日期、签发时间
下拉单选select.ctl证件类型、民族、管理单位
单选组.opts .rad性别、体重情况、婚姻状况
复选组.opts .chk慢病/重点疾病、医疗费用支付方式
级联地址.cascader（多列面板）籍贯、出生地、常住地址
联选择（其他+输入）复选组 + 条件输入框药物过敏史「其他」、家族史
明细表格.mini-tbl，行增删个人健康凭证、手术/外伤明细
分区/分割fv-group 标题按区块组织字段

字段通用属性：字段标识(key)、字段名称(label)、控件类型、是否必填（红色星号 i）、默认值、占位提示、数据长度/精度、所属分区、排序。

FR-04 校验规则配置 核心 · 必做

规则类别说明优先级
必填校验标识必填并联动表单维护.html 的「必填项」配置，参与完整度计算。高
格式校验身份证 18 位、手机号 11 位、日期范围、数字区间、正则表达式。高
枚举/值域校验校验值属于值域目录或字段选项范围。高
条件显隐字段/明细仅在特定条件下展开，如「手术史=有」才显露明细表、暴露史独立成行。高
统计联动如糖尿病分级自动判定（空腹血糖 7.0/10.0 档），手动仍可覆盖。中
完整度分区配置参与完整度计算的区块与权重（参与区块权重和=100%）。高

FR-05 数据标准对齐（WS 363） 核心 · 必做

功能点说明优先级
数据元搜索引用字段编辑时可检索 WS363 数据元目录，绑定标准标识符、名称、值域。高
对齐度评估统计已绑定/未绑定标准数据元的字段比例，生成可导出的符合性清单。高
值域码表复用字段选项从值域目录引用，发布时输出标准码值，保障跨系统互操作。中
上报映射发布时生成字段 key ↔ 数据元标识 的映射元数据，供上报接口消费。中
持久原则：引擎产物是表单结构与标准的映射元数据，而非可执行的硬代码，从而让「改表=改配置」成为现实。

FR-06 版本管理与发布 核心 · 必做

编辑草稿→ 保存草稿→ 提交审核→ 审核通过→ 发布新版本→ 历史数据平滑迁移
功能点说明优先级
草稿保存未发布前可随时保存，不对外可见。高
版本号每次发布递增主版本（如 V1 → V2）；重大变更可提升主版本。高
版本快照发布即固化完整结构快照，记录发布人、发布时间、变更说明。高
回滚可回退到历史任一已发布版本，回滚同样产生新版本并保留审计。中
发布检查发布前强制校验：字段标识唯一、必填完整性、数据元可解析、版本差异预览。高

FR-07 历史数据安全与平滑过渡 重点保障

能力说明优先级
历史版本数据只读保留已归档版本的历史填报数据完整保留、可查询，绝不被新字段删除连带清除。高
字段新增新增字段对历史数据无影响，历史记录该字段标记为空/默认值。高
字段删除/停用仅停用展示，历史存储字段保留；数据迁移按字段 key 映射。高
语义映射字段更名/数据类型兼容变更时提供映射配置，发布后历史值自动过渡。中
审计日志记录每次设计变更，谁在什么时间改了哪些字段，全链路可追溯。中

7 数据模型

表单设计引擎的运行时数据模型，与现有 `表单维护` 的 sections/complete 模型兼容扩展。

Form（表单元数据）

属性说明
key / name / module表单标识、名称、所属业务模块（如 个人档案）
enabled是否启用（联动 表单维护）
currentVersion当前生效版本号
sections[]区块数组，每个区块含 g 分组名、字段、是否参与完整度、权重

Field（字段）

属性说明
k / n / r字段标识 / 名称 / 是否必填（沿用 表单维护 data-set）
type控件类型（text/number/date/select/radio/checkbox/cascader/table/group…）
layout排列方式（single / two-col / ig / table）
deId / deName / deDomain绑定 WS363 数据元标识 / 名称 / 值域码表
options[]单选/复选/下拉的选项
rules[]必填、格式、区间、正则、条件显隐等校验规则
defaultValue / placeholder / maxLength外观与默认行为属性

Version（版本）

属性说明
id / versionNo版本号（V1、V2…）
snapshot发布时的完整结构快照（sections+fields+rules）
publisher / publishTime / changeLog发布人、时间、变更说明
status草稿 / 待审 / 已发布 / 已回退
fieldMapping新旧版本字段映射表，支撑历史数据平滑过渡

8 非功能需求

秒级画布保存与预览响应
兼容性沿用框架.css 设计令牌，支持 iframe 嵌入
权限仅有权机构可发布，操作留痕
类别要求
易用性全程可视化、零代码；关键操作有提示与撤销/重做；字段标示必填红色星号。
兼容性复用 框架.css 设计令牌与 框架.js 导航/嵌入模式；发布职责内正常渲染既有 h 表单。
安全与权限设计/审核/发布职责分离；发布等敏感操作需授权与审计；操作日志可查。
数据一致性字段标识唯一性校验；数据元绑定校验；回滚不破坏历史数据。
性能含数百字段的表单渲染无明显卡顿，画布操作即时反馈。
可扩展字段组件、校验规则、数据元目录均插件式可扩展，支持地方性扩展字段。

9 界面规范（对应 表单设置.html）

表单设置页为三栏式表单设计工作台，整体沿用系统「克制的企业级配置台」风格与 框架.css 设计令牌。

区域内容
顶部页头表单名称、版本号、状态徽标（草稿/待审/已发布）、操作按钮：保存草稿 / 预览 / 提交审核 / 发布。
左栏 A · 结构/组件表单分区树（Tab）与字段组件库：单行文本、数字、日期、下拉、单选、复选、级联地址、明细表格、分区。
中栏 B · 设计画布以 fv-card/fv-group/hp-row/hp-cell 范式实时渲染；字段可点击选中、拖拽排序；点击字段联动右侧属性面板。
右栏 C · 属性面板展示选中字段属性：名称、标识、控件类型、是否必填、默认值、校验规则、WS363 数据元绑定；区块属性：分区名、完整度参与与权重。
页签区字段设计 / 校验规则 / 数据标准 / 版本历史 四个页签。
原型示意：见《表单设置.html》设计画布

10 典型应用场景

场景 A：政策调整快速上线（小时级）

国卫基层发〔2026〕19 号落地，要求随访表新增「服务方式」字段并在特定区间增加必填校验。业务人员在 表单设置 打开随访表 → 拖入单选框「服务方式」（选项：门诊/家庭/远程）→ 绑定 WS363 数据元 → 标记必填 → 保存草稿 → 预览核对 → 提交审核 → 发布 V2。整个过程无需研发介入。

场景 B：地方性表单差异化

某地需在儿童管理表单上叠加地方筛查字段。业务人员「复制表单」为地方版本，在画布新增字段，发布为地方独立版本，不影响国家级统一版本。

场景 C：历史数据平滑过渡

字段「过敏史」由自由文本改为枚举选择。发布时配置字段映射（自由文本 → 枚举「其他」兜底），历史数据完整保留并与新版结构共存。

11 验收标准

#验收项
1业务人员（无代码能力）能在 10 分钟内完成一个含分组、必填、校验的字段表单搭建并预览。
2表单发布后，档案维护对应页面按新结构正常渲染与填报，未发布前不影响现行版本。
3字段绑定 WS363 数据元后可输出符合性清单与上报映射。
4版本变更后历史数据完整可查，新版本字段变更不影响历史记录。
5发布全流程留痕，支持回滚与审计。
6与表单维护.html 的必填项 / 完整度配置双向联动。
