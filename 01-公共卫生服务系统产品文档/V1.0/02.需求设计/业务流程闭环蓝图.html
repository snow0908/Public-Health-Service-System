业务闭环流程图6 个阶段 · 15 个流程节点 · 节点标注对应功能需求编号

关键业务规则（实测提炼）

  • 新建档案必经居民查重弹窗：按身份证号/姓名/出生日期/管理机构/档案编号检索，防止一人多档（实测）
  • 档案编号由系统自动分配（实测建档生成档案编号00100214）
  • 档案上锁后编辑页字段全部只读（disabled），形成档案保护机制（实测）
  • 患者360视图聚合18个业务模块信息，实现"一人一档、全程健康服务视图"（实测）
  • 死亡居民走死亡登记表并触发居民死亡提醒（实测：提醒管理含居民死亡提醒页签）

闭环机制与断点风险

闭环路径：建档提醒 → 建档登记 → 更新提醒 → 动态维护 → 建档率统计反馈催建
  • 死档风险：建档后无动态更新 → 依赖档案更新提醒与动态使用率考核指标闭环
  • 一人多档风险：跨机构重复建档 → 查重弹窗需覆盖全区数据源，建议增加异步查重服务

关键业务规则（实测提炼）

  • 添加家庭成员前必须先保存家庭基本信息，否则提示"请先添加家庭基本信息"（实测）
  • 户主通过家庭基本信息页签的"户主姓名"搜索图标选择居民，并作为第一个家庭成员（实测）
  • 添加成员调用家庭唯一性校验接口（verification_family_uniqueness），一个居民档案只能归属一个家庭（实测）
  • 与户主关系9选项：本人或户主/配偶/子/女/孙子孙女/父母/祖父母/兄弟姐妹/其他；血缘关系6选项（实测）

闭环机制与断点风险

  • 成员与个人档案脱钩风险：家庭档案成员须来自居民档案，避免手工录入产生数据孤岛
  • 扶贫信息年度复核：建议增加年度复核提醒形成扶贫档案更新闭环

业务闭环流程图6 个阶段 · 13 个流程节点 · 节点标注对应功能需求编号

关键业务规则（实测提炼）

  • 老年人编辑表单56字段；评估量表：进餐/梳洗/穿衣/如厕/活动5项，每项4级（可自理0分→不可自理最高分），系统自动合计（实测）
  • 中医体质辨识33题×5级（没有/很少/有时/经常/总是），第9题按BMI分段计分、第14题按感冒频次计分，自动计算9种体质得分与类型（实测）
  • 体检表3页分步：一般情况+生活方式+脏器功能 → 查体+辅助检查+健康问题 → 用药+接种史+健康评价+指导（实测）
  • 体检异常（高血压/糖尿病）应转入对应专项管理，形成老年体检→慢病管理的转化链路（产品设计要点）

闭环机制与断点风险

闭环路径：年度体检计划 → 体检完成 → 能力/体质评估 → 健康指导 → 异常转专项 → 次年计划生成
  • 体检完成率风险：老人行动不便 → 依赖服务计划提醒+团队下乡批量检；建议增加移动端体检录入
  • 评估结果应用不足：自理能力得分应联动分层照护建议，形成评估→干预闭环

04闭环保障机制（产品视角）

流程图描述"应该怎么走"，以下 9 项机制保证"实际走成闭环"——它们是竞品实现闭环的产品抓手，也是重建系统的架构重点。

CL-01查重防重复建档

新建居民档案必经居民查重弹窗（身份证/姓名/出生日期/机构/档案编号5项检索），从源头保证"一人一档"；家庭档案同理调用家庭唯一性校验接口。

关联业务域：BZ-01 / BZ-02
CL-02档案锁与权限保护

档案上锁后编辑页字段全部只读，配合机构/部门数据权限，防止越权篡改档案。

关联业务域：BZ-01
CL-03计划任务驱动

随访/指标参数配置 → 自动生成8类服务计划 → 消息推送 → 执行销项，未完成项持续提醒，是所有服务业务闭环的总发动机。

关联业务域：BZ-18
CL-04消息闭环流转

任务消息支持跳转业务页面直接处理，处理完成即销项；系统通知支持已读管理，形成"推送-处理-反馈"的消息闭环。

关联业务域：BZ-18
CL-05患者360汇聚

所有业务模块的服务记录（随访/体检/报卡/评估）统一写回患者360视图，实现服务过程可追溯、健康信息全汇聚。

关联业务域：BZ-01
CL-06量表自动判定

中医体质辨识（33题自动计分判9体质）、自理能力评估（自动合计）、心血管分层评估等量表引擎自动输出结论，保证评估标准化。

关联业务域：BZ-03 / BZ-12
CL-07转化衔接机制

高危人群→确诊慢病专项、老年体检异常→慢病管理、产后42天→妇女保健、新生儿→儿童档案，业务域之间通过人群状态转化衔接成全程服务链。

关联业务域：BZ-06 / BZ-03 / BZ-09
CL-08统计反馈催办

7张国家报表+工作台进度大屏量化呈现服务完成情况，指标未达标触发催办提醒，最终形成"数据反哺业务"的管理闭环。

关联业务域：BZ-19
CL-09审计追溯

档案查阅记录、操作日志、档案传输记录三类审计日志，保证业务过程可追溯、责任可认定。

关联业务域：BZ-01 / BZ-19

05建设路线建议（MVP 分期）

按业务优先级与依赖关系建议的三期建设路线：档案底座与驱动引擎先行，规范主线保考核，支撑业务与增强项收尾。

MVP · P0 先行（建议 3-4 个月）

  • 档案底座：居民档案（查重/建档/360视图/档案治理）+ 家庭档案（BZ-01/02）
  • 驱动引擎：计划提醒引擎 + 消息中心（BZ-18）
  • 规范主线：高血压 + 糖尿病管理（随访4次/年）（BZ-04/05）
  • 法定报告：传染病报卡 + 突发公卫事件（BZ-13）
  • 妇幼主线：孕产妇 + 0-6岁儿童管理（BZ-09/10）

覆盖国家规范考核权重最高的服务项目，且档案与引擎是全系统地基，先行交付即可支撑基本公卫考核。

二期 · P1 重点（建议 +3 个月）

  • 老年人健康管理（体检/评估/中医药辨识）（BZ-03/12）
  • 重精 + 肺结核管理（BZ-07/08）
  • 其他慢病 + 高危人群管理（BZ-06）
  • 妇女保健 + 两癌筛查 + 母婴阻断（BZ-11）
  • 健康教育服务（BZ-15）
  • 业务报表 + 统计上报（BZ-19）

补齐国家规范全部服务项目与报表上报能力，形成完整公卫服务产品。

三期 · P2 完善（建议 +2 个月）

  • 卫生监督协管（BZ-16）
  • 三网监测（BZ-14）
  • 档案迁移流转（BZ-17）
  • 外嵌能力替代决策：BI大屏/自助查询 自研 vs 外采
  • 闭环增强：高危一键转化、报卡时效倒计时、服药提醒等增强项

支撑性与边缘业务，同时决策第三方依赖的替代方案，完成产品闭环增强。
