一、第一期（1.0）定位、目标与验收口径

1.1版本定位

第一期对应路线图 1.0「规范补齐与平战结合版」（原 3.0 平战结合内容整体提前并入）：先把规范项补齐，解决「有没有、全不全」，并同期具备平战结合与领导驾驶舱能力。原因为「平战结合」是《全国公共卫生信息化建设标准与规范（试行）》一级要求（合规项而非增值项），且驾驶舱/一张图是领导可见度最高的能力，直接影响项目验收与复制推广。

项内容
版本名1.0 规范补齐与平战结合版（第一步「医共体平台补齐」+ 第三步「智慧医院县级延伸」提前实现）
时间窗2026-09 ~ 2026-12；里程碑 M1（09-20 规范基线冻结）→ M2（10-15 原型评审）→ M3（11-15 核心开发完成）→ M4（11-30 内部验证与演练）→ M5（12-01 公司内部发布）

3.6数据层：同源 API + BFF 裁剪 + 离线同步

  • 同一后端、同一 API 契约：三档三端调用同一套接口（I-01~I-12 对接能力在服务端实现），杜绝「移动端另起一套接口」导致的口径漂移；
  • BFF 按端裁剪：PC 返回全字段 + 聚合视图，移动端仅返回卡片所需精简字段（首屏 ≤2 秒的抓手之一），字段裁剪在 BFF 层配置而非业务层复制；
  • 离线能力（C 档硬要求，1.0 原型验证、1.1 正式交付）：本地 SQLite（App）/ IndexedDB（简易 Web）+ 增量同步 + 冲突检测（服务端优先 + 人工裁决）；离线记录带本地时间戳与终端标识，联网后按人、按记录粒度同步；断网可持续作业 ≥72 小时、本地缓存 ≥2000 条；
  • 弱网策略：请求合并、分页拉取、缓存优先（stale-while-revalidate）、失败重试队列；应急一键上报走最高优先级通道。

3.7可视化层：驾驶舱大屏适配

  • 设计基准：以 1920×1080 为唯一设计基准稿，全部页面套用 transform: scale 等比缩放（scale = 目标宽/1920，目标高/1080 取小值），适配 2K/4K/21:9 带鱼屏与拼接屏，等比保证构图不破；
  • 超宽屏补充策略：21:9 及以上在等比缩放基础上启用「模块弹性延展」（地图、热力图容器优先拉伸，文字模块锁定宽度），避免两侧大面积留白；
  • 图表自适应：ECharts 统一监听容器 resize；文字最小可读字号 ≥12px（物理像素），4K 屏下不出现「缩得过小」；
  • 值守模式：大屏轮播（一张图 → 责任清单 → 热力图 → 应急态势），轮播间隔与页面序列可配置，服务应急值守场景；
  • B 档只读：同一驾驶舱应用挂载只读开关（隐藏钻取/导出/交互入口），复用全部渲染代码。

3.9设计系统层：Design Token 三端共享

  • 一套 Token 源：色彩语义（主色/成功/警示/危险/信息）、字号阶梯、间距（4px 基数）、圆角、阴影、动效时长统一定义，导出为 Web CSS Variables 与移动端主题变量，三端视觉同源；
  • UED v1.6 为 PC 基线：组件库在 v1.6 基础上补齐「双形态」能力（每个业务组件提供 desktop / mobile 两个视图实现、共享 props 与逻辑），而非另建移动组件库；
  • 一致性红线：同一业务动作（如「随访」「报卡」「建档」）在三端的命名、图标、色彩语义完全一致——村医在手机上看到的「红黄绿」与公卫科在 PC 上看到的分级颜色语义一致；
  • 档位不改变设计语言：A/B/C 三档视觉规范相同，差异仅在功能可见性与交互密度（验收判据「三档界面符合 UED v1.6」）。

3.10工程与测试层：多分辨率质量门

  • 视口快照回归：Playwright/Puppeteer 按「断点 × 档位 × 关键页面」矩阵自动截图比对，纳入 CI，防响应式回归；
  • 分辨率测试矩阵（示例）：6 个视口（375 / 768 / 1280 / 1440 / 1920 / 3840）× 3 档功能开关 × 10 个关键页面（档案列表、随访录入、家谱图、报卡、驾驶舱、任务看板、报表、质控整改、居民端档案、授权页）≈ 180 组快照用例；
  • 真机测试：C 档覆盖低端安卓（≤2GB RAM）、iPhone、国产定制系统各 ≥1 台；驾驶舱在 1080p/4K 实屏验证；
  • 离线演练：断网 72 小时连续作业 + 冲突裁决用例（并入 M4 内部验证）；
  • 验收对照：三档界面符合 UED v1.6、C 档离线 72h、移动首屏 ≤2s 直接引用 02 文档 8.2 验收判据。
